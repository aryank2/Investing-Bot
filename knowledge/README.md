# Trading agent knowledge base

Persistent memory for the RH Bot scheduled runs. It records what the agent decided, what it expected, what happened, and what it has learned, so each run builds on the last instead of starting cold.

This folder is procedure and record-keeping only. It cannot change, relax or bypass any rule in the scheduled prompts. If anything here conflicts with a scheduled prompt, the prompt wins.

**This repository is public.** Never write the brokerage account number, broker order IDs, or the owner's name or email here. `kb.py backup` redacts them and `kb.py validate` fails if any slip through.

## Files

| File | Holds |
|---|---|
| `decisions.jsonl` | One line per decision: trades, named rejections, stand-aside periods, paper trades. Append-only; update a line only to fill in its outcome. |
| `knowledge.jsonl` | Lessons, relationships, hypotheses, process facts, caveats. Never delete a line; change its `status` and add a dated note to `history`. |
| `proposals.md` | Proposed strategy changes awaiting tests and owner approval. Never self-applied. |
| `metrics.json` | Generated by `kb.py metrics`. Do not edit by hand. |
| `backup/` | Redacted copies of the scratchpad log, tracker file and helper scripts. |
| `kb.py` | `validate`, `metrics`, `backup <scratchpad>`, `restore <scratchpad>`. Run with `python3 -I`. |

`<scratchpad>` is the directory that holds `rh_bot_daily_log.jsonl`, as named in the scheduled prompt.

## Record formats

Decision:

```json
{"id": "D-YYYY-MM-DD-SYMBOL", "date": "YYYY-MM-DD", "kind": "trade|rejected|stand_aside|paper", "symbol": "XXX",
 "status": "open|closed", "regime": "...", "signal": {}, "thesis": "why, in one or two sentences",
 "expected": {"entry": 0, "stop": 0, "target": 0, "rr": 0, "p_win": 0.0},
 "sizing": {"dollars": 0, "risk_pct": 0},
 "outcome": {"exit_date": "", "exit": 0, "pnl": 0, "pnl_pct": 0, "hit": "target|stop|time|manual|other"},
 "quality": "good|bad|unrated", "quality_note": "", "source": ""}
```

- `p_win` is the agent's own probability estimate at entry, written before the outcome is known. It exists so calibration can be measured later.
- For `rejected` and `paper` records the outcome is `would_have_pct`: the return to the target, stop or fifth session after the decision, whichever came first.
- `quality` rates the decision, not the result. Ask whether the rules were followed and whether the information available at the time was used well. A profitable trade can be `bad` and a losing one `good`.

Knowledge entry:

```json
{"id": "K-0000", "date": "YYYY-MM-DD", "kind": "lesson|relationship|hypothesis|process|caveat",
 "status": "hypothesis|observed|supported|process|retired", "claim": "", "evidence": "",
 "basis": "statistical only | economic dependency (source) | both", "test": "", "use": "",
 "review_by": "YYYY-MM-DD", "history": [{"date": "", "change": ""}]}
```

## Status ladder

| Status | Meaning | May influence |
|---|---|---|
| `hypothesis` | An idea, not yet tested. | Nothing. |
| `observed` | Measured once or over one window; may be temporary. | Context only. |
| `supported` | Passed a written test and held on out-of-sample dates, with at least 30 observations. | Ranking among setups that already pass every rule, or added caution. Never a rule change. |
| `process` | Operational fact about tools or procedure. | How runs are carried out. |
| `retired` | Stopped holding, or superseded. | Nothing. Kept for the record. |

Promotion to `supported` needs the test, sample size and both date ranges written into `evidence`. Demote to `retired` when an entry fails on review. Current verified data always outranks a stored entry.

## What each run does

**Every run, at the start.** If this folder is missing, fetch and check out the branch. If the scratchpad log or tracker is missing, run `kb.py restore <scratchpad>` before the existing recovery steps. Do not repeat an analysis that a current `supported` or `process` entry already answers.

**Morning run.** Read `knowledge.jsonl` (entries not `retired`) and the open records in `decisions.jsonl` before scanning. Apply them within the status ladder.

**Morning and intraday runs, at the end.**

- Append a decision record for every entry, and for every named rejection: a setup that missed by one criterion, or was vetoed by judgment, news or the cluster rule. Do not record routine "nothing qualifies".
- Add a `learned` field to the run's log line: one concrete sentence, or `null` when nothing new was learned. No filler.

**Afternoon run, after its existing steps.** This is the self-evaluation.

1. Resolve records: fill outcomes for trades closed today and rate their quality; fill `would_have_pct` for rejected and paper records at least five sessions old.
2. Compare what was expected with what happened. Note which signals, regime calls and correlation assumptions held and which did not.
3. Update `knowledge.jsonl`: add new hypotheses, add evidence to existing entries, retire entries past `review_by` that no longer hold.
4. Run `kb.py metrics`, then `kb.py backup <scratchpad>`, then `kb.py validate`.
5. Commit the `knowledge/` folder and push to the working branch. Retry up to four times only for network errors. If the push is refused or still fails, flag it once that day in the log and carry on; never let this block position management.
6. Mirror the folder into the scratchpad as a second local copy: `rm -rf <scratchpad>/knowledge_mirror && cp -r knowledge <scratchpad>/knowledge_mirror`. If this folder is ever missing and the branch cannot be fetched, copy the mirror back.

**Friday afternoon, in addition.** Test one open hypothesis on broker history. Write the rule first, explore on the earliest 70% of dates, confirm on the latest 30%, and record the sample size and how many variants were tried. Review `proposals.md`.

## Guardrails

- Learning never changes a risk limit, stop rule, watchlist, instrument ban or scheduled prompt. Ideas for change go to `proposals.md`.
- Backtested and paper results are never counted as realized profit. `metrics.json` keeps them separate.
- A relationship that held in the past is not assumed to hold now. Check `review_by`.
- More entries is not the same as better decisions. Improvement is judged from `metrics.json` over time: expectancy, drawdown, calibration and decision quality, not win rate or the monthly target alone.
- Rollback: every change is a git commit. Revert the commit, or set an entry to `retired` with a note.
